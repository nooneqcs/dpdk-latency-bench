# rq-bench — DPDK 低延迟数据路径实测

单核单队列下，测 DPDK 收发路径各段成本，以及 1GbE 线速上限。
所有数字可在本机用 ./run_all.sh 复现。

## 硬件与软件

- CPU：i5-7400（4C4T，base 3.0 GHz，no_turbo=1）
- 系统：Ubuntu 25.11，内核 7.0.0-43-generic
- DPDK：25.11
- 网卡：Intel i210 [8086:1533]，绑 vfio-pci，1000M 全双工
- 对端：Realtek USB GbE（A0:CE:C8:E4:FC:74），用作发流
- TSC：3.00 GHz invariant

未做核隔离（isolcpus / nohz_full）与关中断，因此 p99.9 不可控，本文只报 p50/p99。

## 怎么跑

- ./run_all.sh fast  —— 7 项，约 40 秒，不需要外部流量
- ./run_all.sh full  —— 额外含 rx / end2end，需要笔记本侧发流

结果写入 runall-<时间戳>/。参考输出见 RESULTS.md，完整会话见 RUN-SESSION.md。

## 测量口径

- 净值：已扣除一次 rdtsc_precise 的计时开销。本机实测为 77.7 cycles = 25.9 ns（见 rdtsc_bench），所有"测得的段值"都要减 25.9 才是净成本。
- 空环 / 零在途：每轮发送前把 TX 环 drain 到空（rte_eth_tx_done_cleanup 返回 0）再开始计时。
- 批均：每轮 rx_burst 实际取到的包数（本机多数为 1.0）。
- 热数据：包刚 DMA 到内存、仍在 cache 中；冷数据指从 DRAM 读取。
- 分段不可加：解析、发送各自扣一次 25.9 ns，拼成端到端时会多扣一次，所以端到端以直接测的值为准，分段只用于看占比。

## 主要结果（测得 / 净值）

- 空轮询（rx_burst 返回 0）：6.4 ns
- 取包 100 pps：p50 172 / p99 487（净 p50 146）
- 解析（热数据，16 字节字段）：37.6 / 12
- 解析（90 字段 AVX2，批量）：9.7（批量摊薄，无偏差）
- CTP 408 字节报文（V3 memcpy+大端）：10.1 / 8.7
- 发送 100 pps：236 / 210
- 发送 7.4 万 pps：155 / 129
- 发送 空环单包：142 / 116
- 发送 32 包批量（每包）：22.7 / 21.9
- 端到端 100 pps / 400 B：约 250（净）
- 端到端 7.4 万 pps：约 166（净）
- 64 B 帧线速：1,488,135 pps，100.0%（理论 1,488,095）

包长 64 → 400 字节端到端无变化（<1%），说明成本在每包固定开销，不在数据搬运。

## 已知限制

- 负载是合成的（UDP 广播、固定包长、恒定速率），不等于真实 CTP 行情（TCP、408 字节、多合约、突发）。
- 单核单队列；1GbE 上线速已达 100%，多核无意义（单核能力约 6.7 Mpps，远超 1GbE 的 1.49 Mpps）。
- 线速 100% 是网卡能力，只说明应用层不构成瓶颈，不应当作软件成绩。
- 未做核隔离，p99.9 在 25–160 μs 间波动，不对外报。

## 测量修正记录

本仓库的数字经过三轮修正，历史 commit 保留了当时的原始结论：

- 初测（作废）：处理段 140 ns。当时 i210 链路未通，tx_burst 只把描述符写进环就返回，包实际没有发出。
- 链路修复后重测：端到端 461 ns（低频，约 1 pps）与 181 ns（高频，7.4 万 pps）。两者差异来自发送频率对描述符缓存状态的影响，不是矛盾。
- 发现 rdtsc_precise 的计时开销为 25.9 ns（77.7 cycles），对所有段值统一扣除，得到最终净值。

另外两次同类问题：

- tx_bench 曾长期 opackets=0，根因是每档调用 rte_eth_dev_stop/dev_start 导致 igb TX 队列失效，与硬件、vfio 无关。
- 64B 线速早期记录为 1,420,485 pps（95.46%），复核为 1,488,135 pps（100%），旧数口径不同。

保留这些记录的理由：测错的数比正确的数更能说明测量方法本身的重要性。
